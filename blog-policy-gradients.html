Policy gradients with two buttons

This uses the same slot machine as the RL loop post, where button A pays out 30% of the time and button B pays 70%. In that post the agent kept an average payout for each button. A policy gradient method skips the averages and stores the thing you actually care about, which is how likely the agent is to press each button.

The update rule is short. Press a button according to the current probabilities, and if a coin comes out, make that button a bit more likely.

import math, random

pay = [0.3, 0.7]       # hidden from the agent
pref = [0.0, 0.0]      # one preference per button

for step in range(2000):
    e = [math.exp(x) for x in pref]
    p = [x / sum(e) for x in e]              # probabilities

    a = 0 if random.random() < p[0] else 1   # sample a button
    r = 1 if random.random() < pay[a] else 0

    for i in range(2):
        grad = (1 - p[i]) if i == a else -p[i]
        pref[i] += 0.1 * r * grad

print(p)   # about [0.01, 0.99]

pref holds one number per button and the softmax lines turn those into probabilities. The grad line is the only slightly opaque part. For the button that was pressed it is 1 - p, so the push is large when that button was unlikely and shrinks as it becomes the favourite, and the other button gets pushed down by a matching amount. When r is 0 nothing moves. After 2,000 presses the policy sits at about 1% A and 99% B.

You hit a weakness quickly. Suppose A always pays 10 and B always pays 11. Both rewards are positive, so whichever button gets pressed becomes more likely, and the policy only drifts toward B slowly because B's pushes are slightly bigger. The standard fix is to subtract the average reward first. With a baseline of 10.5, A scores −0.5 and B scores +0.5, so A now gets pushed down and B gets pushed up. That "reward minus what you'd normally get" number is called the advantage.

RL on a language model works the same way. The model is the policy, the next token is the action, and training makes the tokens of better-than-average answers more likely. GRPO is one way of deciding what "average" means.
