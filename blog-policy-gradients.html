Policy gradients, from scratch

November 13, 2026 · 3 min read

If an action got a reward, make that action more likely.

That sentence is the full method. The rest is arithmetic.

A policy is a set of probabilities

In the first post, the agent kept an average reward for each button. Here the agent keeps something more direct: the probability of each action.

Button AButton B
At the start50%50%
After learning1%99%

To act, the agent samples from these probabilities. No explore rule is necessary. The sampling does the exploring.

The update

  1. Sample an action.
  2. Get the reward.
  3. If the reward is high, raise the probability of that action. The other actions go down.

The size of the change is in proportion to the reward. Zero reward gives zero change.

The code

Button A pays 30% of the time. Button B pays 70%. Each button has a preference number. A softmax changes the preferences into probabilities.

import math, random

pay = [0.3, 0.7]       # hidden from the agent
pref = [0.0, 0.0]      # one preference for each button

for step in range(2000):
    e = [math.exp(x) for x in pref]
    p = [x / sum(e) for x in e]              # probabilities

    a = 0 if random.random() < p[0] else 1   # sample an action
    r = 1 if random.random() < pay[a] else 0

    for i in range(2):
        grad = (1 - p[i]) if i == a else -p[i]
        pref[i] += 0.1 * r * grad            # push toward what paid

print(p)   # about [0.01, 0.99]

The agent now pushes button B 99% of the time. This method is named REINFORCE.

The problem: every reward looks good

Change the rewards. Button A always pays 10. Button B always pays 11.

Both rewards are positive. So each action makes its own probability go up, and learning is slow and noisy.

The fix is to compare with the average. Subtract the average reward, the baseline, from each reward.

ButtonRewardReward − baseline (10.5)Effect
A10−0.5Less likely
B11+0.5More likely

The number "reward − baseline" is the advantage. It answers one question: was this action better than usual?

Why this matters for language models

A language model is a policy. The state is the text so far. The action is the next token. The model gives a probability to each token.

So the same rule trains a language model: if an answer got a reward above the baseline, make its tokens more likely.

Sample, score, and make better-than-usual actions more likely.
