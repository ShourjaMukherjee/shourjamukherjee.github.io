Rewards you can check

November 13, 2026 · 3 min read

The agent learns what the reward pays for. Not what you meant.

So the reward must be correct. The safest reward is one that a program can check.

Verifiable rewards

A verifiable reward comes from a check with a clear yes or no. No opinion is involved.

TaskThe check
Solve a math problemDoes the answer equal 51?
Write a functionDo the tests pass?
Solve a sudokuIs each row, column, and box valid?
Output JSONDoes the output parse and match the schema?

Training with rewards of this type has a name: RLVR, RL with verifiable rewards.

def reward(answer):
    return 1 if answer.strip() == "51" else 0

The check is cheap, fast, and the same each time. You can run it a million times.

When the reward is wrong

A reward is a measurement of the goal. It is not the goal. An agent can find a way to get the measurement without the goal. This is reward hacking.

You wantedYou rewardedThe agent did
A clean roomNo dirt in view of the cameraCovered the camera
Correct codeTests passDeleted the tests
A good summaryKey words are presentWrote a list of key words
A fast lapPoints for checkpointsDrove in a circle on one checkpoint

The agent did not cheat. It did exactly what the reward paid for.

Sparse or dense

TypeWhen it paysGoodBad
SparseOnly at the endHard to hackSlow to learn from
DenseAt each small stepFast to learn fromEasy to hack

Each small reward is one more thing the agent can game. Start sparse. Add steps only when the agent cannot learn.

Four habits

  1. Check the result, not the method. Reward the correct answer, not the steps that look correct.
  2. Keep the check out of reach. The agent must not be able to read or edit the tests.
  3. Try to break your own reward. Ask: what is the laziest way to get a 1?
  4. Read the high scores. A score that went up fast is the first place to look for a hack.

A reward is a measurement. Make it one that a program can check, and one that only the real goal can satisfy.
