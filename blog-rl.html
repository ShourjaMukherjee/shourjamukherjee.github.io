The RL loop in 15 lines of Python

Most RL explanations open with a diagram of an agent and an environment. I find it easier to start with a slot machine that has two buttons. Button A pays out 30% of the time and button B pays 70%, and the program doesn't know that. All it can do is press a button and see whether a coin comes out.

import random

pay = [0.3, 0.7]      # hidden from the agent
Q = [0.0, 0.0]        # the agent's estimate for each button
N = [0, 0]            # presses per button

for step in range(1000):
    if random.random() < 0.1:
        a = random.randrange(2)      # explore
    else:
        a = Q.index(max(Q))          # exploit
    r = 1 if random.random() < pay[a] else 0
    N[a] += 1
    Q[a] += (r - Q[a]) / N[a]        # running average

print(Q, N)   # about [0.26, 0.71], [139, 861]

The agent keeps a running average of what each button has paid so far and mostly presses whichever one looks better. After each press it moves that button's average toward what just happened. After 1,000 presses the estimates were 0.26 and 0.71 and it had pressed B 861 times, and it got there from the payouts alone, with no labels anywhere.

The part that is easy to skip over is the 0.1. One press in ten is random. If you take that out, the agent can get unlucky: A pays on the first press, A's average goes above zero, and from then on A always looks better than a button it has never tried, so it presses A forever. That single line is the explore/exploit tradeoff, and every RL method has some version of it.

The other thing this toy hides is delay. Here the reward shows up right after the press. In most real tasks it shows up much later, like a chess game where you only learn the result after forty moves and then have to work out which of them mattered. Most of the machinery in RL, such as returns, discounting and value functions, exists to deal with that credit assignment problem.
