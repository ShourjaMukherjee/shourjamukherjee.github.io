An RL environment is two functions

"RL environment" sounds like a big simulator, but the interface is tiny. You need reset(), which starts a new attempt and returns the first state, and step(action), which applies one action and returns the new state, a reward, and whether the attempt is over.

class Corridor:
    def reset(self):
        self.pos = 0
        return self.pos

    def step(self, action):              # -1 = left, +1 = right
        self.pos = max(0, self.pos + action)
        done = self.pos == 4
        reward = 1 if done else 0
        return self.pos, reward, done

This is a corridor with five cells. You start in cell 0 and get a reward of 1 when you reach cell 4. Here is an agent that moves at random.

import random

env = Corridor()
state = env.reset()
done = False
steps = 0

while not done:
    action = random.choice([-1, 1])
    state, reward, done = env.step(action)
    steps += 1

print(steps)   # about 20 on average

The shortest path is 4 steps and the random agent takes about 20 on average, and that gap is what a learning algorithm has to close.

Writing the two functions is the easy part. The design work is in four choices: what the agent gets to see (the state), what it is allowed to do (the actions), what counts as good (the reward), and when an attempt ends. The reward is the one I would spend the most time on, because the agent optimises exactly what you wrote down, including the parts you didn't think through.

The same shape carries over to language models. For a "fix this bug" environment, the state is the task description plus the repo, the actions are things like reading a file, editing a file or running a command, the reward is 1 if the test suite passes, and the episode ends when the model says it is done or runs out of steps. A task is one starting point in that environment, and a single environment can hold thousands of them.
